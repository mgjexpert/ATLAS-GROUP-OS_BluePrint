# 02 — Organization & Operating Model

## Group hierarchy

```text
PDG / Chairman (Human)
        |
Atlas.Personal / Chief of Staff
        |
Atlas.DG / Group General Director
        |
Executive Committee
|-- Technology / Atlas.Dev
|-- Operations / Atlas.Admin
|-- Commercial / Atlas.Sales
|-- Growth / Atlas.Growth
|-- Content / Atlas.Content
|-- Research / Atlas.Research
|-- Finance Ops / Atlas.FinOps
|-- Governance / Atlas.Governance
```

Agent titles are operating roles, not legal corporate officers unless a human/legal process explicitly defines otherwise.

## Agent workforce model

Every agent should have:
- agent ID;
- role;
- department;
- manager;
- skills;
- tools;
- permission profile;
- model policy;
- budget;
- KPIs;
- current tasks;
- version;
- status;
- evaluation history.

Agents do not have to be permanently running processes. Most should be provisioned or invoked for jobs and terminate when work is complete.

## Business-unit model

Hierarchy:

```text
Organization
  -> Business Unit
      -> Branch / Venture
          -> Team
              -> Agent / Human
```

A branch receives:
- mandate;
- budget;
- objectives;
- policies;
- allowed tools;
- service catalog;
- knowledge;
- reporting obligations.

## Autonomy levels

### L1 — Observe
Read and analyze only.

### L2 — Recommend
Prepare plans/actions for approval.

### L3 — Execute bounded
Perform approved classes of actions within defined limits.

### L4 — Manage
Manage a unit within budget and policy.

### L5 — Autonomous branch
Plan, delegate and operate a branch within a constitutional mandate, with material decisions still escalated.

## Internal service economy

Atlas units can provide services to other Atlas ventures.

Examples:
- Atlas Content produces an ebook for LeveLab.
- Atlas Dev builds a MyTrainX feature.
- Atlas Growth operates a FaceLove acquisition campaign.
- Atlas CX provides customer service to an owned venture.

This permits cost attribution and internal transfer pricing without duplicating specialist teams.

## Project and decision discipline

Every material initiative should have:
- goal;
- owner;
- budget;
- success criteria;
- dependencies;
- risk level;
- current state;
- evidence;
- next decision.

Board-level decisions should create a durable decision record:
- proposal;
- analysis;
- alternatives;
- risks;
- decision;
- approving human;
- budget;
- deadline;
- later outcome.
